## 二、本轮优化收尾（提交 `1652e59`）

### 2.1 P1 / N5 收尾：折线段3 常数 `37027` → **`36428`**

正确的联动推导已写入代码注释：

```
连续性条件: c3 = 段2(x=1.0) - (1/8 + 1/16)
            = (32768 + 4096 + 11852)/65536 - 0.1875
            = 0.743347 - 0.1875 = 0.555847  ->  Q16 = 36428
```

实测效果：

| 边界 | 修复前 | **修复后** | 与真实 tanh 的误差 |
| :--- | ---: | ---: | ---: |
| x = 0.5 | 0.0011 | 0.0011 | −0.0011 |
| **x = 1.0** | **0.009171** | **0.000031** | −0.0182 |

跳变降至 **3×10⁻⁵**，折线已实质连续。代价是 x=1.0 处与真实 tanh 的误差从 −0.0091 增至 −0.0182——**这是正确取舍**：能量泵控制中"消除阶跃抖振"比"逐点贴合 tanh"重要得多，且 1.8% 的幅值误差对起摆轨迹无实质影响。

## 五、唯一剩余缺口：F13-b 动力学 HIL 闭环

### 5.1 为何这是关键缺口

四轮检查中，**三次“TB 全绿但功能失效”的事故均源于同一根因**：

| 轮次 | 被掩盖的缺陷 | 为何没被 TB 抓到 |
| :---: | :--- | :--- |
| 二轮 | F1 cos 表符号翻转、F2 能量判据缺失 | TB 只注入固定 ADC 码值，θ̇ 单调衰减至 0，永远不进大角度动态区 |
| 三轮 | N1 定标错 65536 倍 | 同上；TB 采样点恰好落在死点扰动分支，`energy_deficit` 碰巧为 1 |
| 本轮 | 4 拍延迟断言陈旧 | TB 根本没被运行 |

开环 TB 能验证的只是“**给定输入→输出是否符合预期**”，无法验证“**闭环后系统是否收敛**”。而赛题基础要求 1/3 与拓展要求 3 的验收指标全部是闭环指标：

- 基础要求 1：「静止下垂的摆杆能够被抬起…最终停在垂直位置附近」
- 基础要求 3：「长时间保持稳定不倒下」「抵抗轻微外部推力并在短时间内恢复」
- 拓展要求 3：「位置控制过程中摆杆始终保持直立」

这四项**至今无任何 RTL 级证据**。

### 5.2 实施方案

将 [`simulation/dynamics.py`](file:///c:/Users/28399/Desktop/赛道/simulation/dynamics.py) 的欧拉-拉格朗日方程移植为 Verilog 行为级被控对象模型：

| 要素 | 设计 |
| :--- | :--- |
| 文件 | `src/furuta_plant_model.v`（纯 TB 组件） |
| 数据类型 | `real`，**仅行为级仿真用** |
| 综合隔离 | 整体用 `` `ifndef SYNTHESIS `` 包裹，且在 `.gprj` 中 `enable="0"` |
| 积分器 | RK4，`dt_phys = 0.2 ms`（与 `config.py` 一致，每个 1ms 控制周期内步进 5 次） |
| 接口 | 输入 `pwm_duty`（±1000）→ 换算电压→力矩；输出 θ / α 反算为 **12-bit ADC 码值**与 **4000 CPR 正交脉冲**，回注 `j280_hw_top` 的 `adc_miso` 与 `enc_a/enc_b` |
| 传感器模型 | 含 12-bit 量化 + 可配高斯噪声（`sensor_noise_std = 0.001 rad`） |
| 验证指标 | 起摆成功率（10 次扰动下的成功比）、起摆耗时、平衡保持时长（目标 ≥60s）、抗推力恢复时间 |

**关键技术点**：TB 必须把 θ 反算为 ADC 码值并驱动 SPI 从机行为模型（可复用 `j280_hw_top_tb.v` 已有的 `negedge adc_sclk` 移位发送逻辑），而非直接写内部信号——否则绕过了 `angle_sensor_reader` 的量化与滤波，又会回到开环老路。

### 5.3 本轮已做的阶段性 mitigation

在 HIL 建成前，`swing_up_ctrl_tb.v` 的 35 组矩阵已能覆盖**能量判据的全定义域**（含过零临界），这已排除了 N1/N2 类定标错误重现的可能。但它仍**无法**回答收敛性问题。

## 六、待确认的硬件信息（下板前必须澄清）

经四轮检查仍无法从代码与文档推断的 5 项：

1. **板载晶振是否确为 50 MHz** —— 全部模块 `CLK_FREQ_HZ` 按 50 MHz 参数化。若实为 27/24 MHz，1ms 节拍、SPI 2.5MHz 分频、PWM 20kHz 载波全部偏移。
2. **摆杆角度传感器确切型号** —— [`angle_sensor_reader.v`](file:///d:/Gowin_fpga/edu/project/furuta_lqr_ctrl/src/angle_sensor_reader.v) 仍硬编码 `adc_latch <= shift_reg[11:0]` 且无 MOSI 输出：
   - **MCP3201**：首 bit 为 null，12 位数据落在 `shift_reg[12:1]` → **当前位对齐错误**；
   - **AS5048A / TLE5012B**：**必须发命令字**，当前单向 SPI 无法工作；
   - **ADS7886**：12 位 MSB-first 紧接 CS 下降沿，需核对是否多采 4 bit。
3. **电机驱动是否确为 TB6612FNG** —— 决定 `stby_out = motor_en | brake_mode` 的正确性。
4. **J280 底板原理图 / 引脚分配表** —— CST 的 20 个引脚在 PG484 封装中合法（PnR 已接受、Vccio 匹配、clk 落在 GCLKT_2），但**是否对应底板实际连线无法由 EDA 工具验证**；DS102 为芯片级手册，不含底板连线信息。
5. **电机供电是否确为 12 V** —— `VOLT_TO_PWM_18 = 85333` 与起摆核 `×15` 系数均基于 12V；若为 24V 则增益翻倍，两者需同步重算。

## 八、终审结论

经四轮迭代与本轮优化收尾，选题一 FPGA 旋转倒立摆控制系统已达到：

1. **算法链完整且数值正确**：能量泵起摆 → 双重捕获 → LQI 自平衡 → 积分消静差 → 定点/正弦轨迹跟踪全链已实现，关键定点路径经 **Python 逐位复现 + 45 组 RTL 断言** 双重验证；
2. **工程实现可交付**：Fmax 63.868 MHz、最小 Slack 4.343 ns（裕量 21.7%）、零违例、零综合警告、DSP 88%、引脚 20/20 约束，bitstream 已生成；
3. **回归体系可信赖**：3 个 TB 均真正执行（59 PASS / 0 FAIL / 0 ERROR），入口统一为 `sim_modelsim/run_all.bat`，过期副本已清除。

**尚不能声称“完全满足赛题”**，原因是两项验收指标本质上无法由开环测试证明：

- 基础要求 3（长时间稳定与抗扰）
- 拓展要求 3（运动中保持直立）

这两项需 §5.2 的动力学 HIL 闭环才能回答。**建议将其作为下板前的最后一项工作**；若时间紧迫必须先行下板，则应严格按 §六 澄清 5 项硬件信息（尤其是角度传感器型号与底板引脚表），并按 `doc/J280套件硬件实物检测与校准实操指南.md` 的 SOP 逐步上电调试。
